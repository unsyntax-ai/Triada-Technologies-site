# Mobile version: how it is built and how it is kept apart from desktop

The phone experience (bottom tab bar, glass top bar, app-style controls) is added to the existing site. It is not a second site.
Desktop and tablet (anything wider than 700px) must look and behave exactly as before.

## Files

### Mobile-only (new files; safe to change without touching desktop)
| File | What it does | Applies when |
| --- | --- | --- |
| `assets/mobile.css` | The whole phone layout: glass top bar, bottom tab bar, tiles, rails, timeline, icon rows, sticky Apply bar. | Only up to 700px wide (the `<link>` has `media="(max-width: 700px)"`). |
| `assets/mobile-base.css` | Hides every phone-only element at all other widths and styles the "Mobile site" pill. Contains no layout rules for desktop. | All widths, but it only sets `display: none` on phone-only elements. |
| `assets/mobile.js` | Phone behaviour: type chips, "I am" switch, industry tiles, job Apply bar, the Desktop/Mobile switch. Builds controls on top of existing fields, which stay the source of truth. | Runs everywhere, acts only when the viewport is at most 700px and desktop view was not chosen. |

### Shared (generated or loaded by every page; change with care, test desktop and mobile)
| File | Mobile-related change |
| --- | --- |
| `build.py` | Adds, once, in the shared page template: the two mobile stylesheet links, an early inline script for the Desktop-site switch, the Desktop switch button and optional back button in the header, the bottom tab bar, the "Mobile site" pill, `mobile.js`, the Home quick actions / photo tag / hire-work switch, and the Services contact block. All of these are hidden by `mobile-base.css` outside the phone layout. |
| All `*.html` | Generated by `build.py`. Never edit by hand. Re-run `python3 build.py`. |

### Protected desktop files (not changed by the mobile work)
`assets/site.css`, `assets/site.js`, `assets/jobs.js`, `assets/find.js`, `assets/admin.js`, `assets/jobs-config.js`, `scripts/*`, `supabase/*`, `.github/workflows/*`.

## Rules for future mobile changes
1. Put phone styling in `assets/mobile.css` only. Do not add phone rules to `assets/site.css`.
2. Put phone behaviour in `assets/mobile.js`. Do not edit `site.js` / `jobs.js` for phone features. Read existing fields; do not replace them.
3. New phone-only markup goes in `build.py`, with a class that is hidden in `assets/mobile-base.css`.
4. Never change an existing class's meaning or the desktop breakpoints (`max-width: 700px / 800px / 900px` rules in `site.css`).
5. If a shared file must change, run the regression below on desktop and mobile before accepting it.

## Desktop / Mobile switch
- The top bar shows "Desktop". Choosing it stores `triada-view=desktop` in `sessionStorage` (this tab only), swaps the viewport to 1200px wide, turns off `mobile.css`, and shows the normal desktop site with a "Mobile site" pill to go back.
- Nothing is kept after the tab closes: no localStorage, no cookies, and the page entry is replaced rather than added to history.

## Regression check (desktop must stay identical)
1. `python3 build.py`
2. Serve a pristine copy of the production site and this branch side by side.
3. For every page and for widths 701, 768, 820, 844, 932, 1024, 1180, 1366, 1440, 1920, 2560, compare each element's position, size and key styles (see `TESTING-REPORT.md`). Any difference is a regression.
4. Phones: run the page checks at 360, 390 and 430px, plus landscape 568, 667 and 700px.
